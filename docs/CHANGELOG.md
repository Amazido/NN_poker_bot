## 2026-08-08 — Инициализация проекта: модель, логин, движок раундов

**Было:** пустой репозиторий.

**Стало:** заложена архитектура и первая рабочая вертикаль Одесского покера:
- Модель данных и миграция `0001_initial`: `users`, `rules_editions` (редакция
  правил + мета, версионируется), `game_rooms`, `room_players`, `game_rounds`,
  `round_actions` (append-only журнал).
- Логин через Telegram WebApp (проверка initData HMAC-SHA256) + dev-логин (DEBUG),
  JWT, `GET /auth/centrifugo-token`.
- Движок раундов (`poker/engine.py`) как чистый конечный автомат: сдача, вскрытие
  козыря, торги с «крюком», розыгрыш взяток, подсчёт, переход по раундам матча
  (`18 + n`).
- Старшинство карт (`poker/cards.py`) с козырем, двумя джокерами и пустышками.
- Стейт-движок в Redis (источник истины) + публичный/приватный views + публикация
  в Centrifugo (каналы `room:{id}` и `user#{id}`).
- Инфраструктура: Docker Compose (dev/prod), Dockerfile, seed дефолтной редакции.

**Почему:** задача — сделать серверную основу игры под Telegram WebApp с быстрым
обменом событиями по WebSocket; выбран FastAPI + Postgres + Redis + Centrifugo,
переиспользованы проверенные паттерны из референса `TG-game`.

**Зафиксированные решения по правилам (дефолтная редакция `odessa_classic v1`):**
- Некозырной джокер — «второй сверху»: бьёт все обычные карты, но проигрывает
  козырю и козырному джокеру.
- Джокер, ведущий взятку, не задаёт масть сброса (остальные свободны).
- Перебор → фикс `−5`; недобор → `−10` за взятку; точный заказ → `+10 × взятки`;
  заказ 0 и взято 0 → `+10`.
- Игроков 3–5, пик карт всегда 10.

**Допущение (в исходных правилах не описано):** в раунде без козыря старший
джокер — тот, что вскрыт ведущим колоду; второй джокер слабее; оба бьют любые
обычные карты. Может быть изменено отдельной записью.

## 2026-08-08 — Локальный веб-тестер и первый прод-деплой

**Было:** только бэкенд; способа «пощупать» игру и развёрнутого окружения не было.

**Стало:**
- `frontend/index.html` — статический веб-тестер (ваниль, без сборки): несколько
  игроков в одном окне, торги/ходы, обновление поллингом; адрес API вычисляется
  по текущему хосту.
- В `docker-compose.yml` добавлен сервис `frontend` (nginx :3000), `DEBUG` вынесен
  в переменную окружения.
- Прод развёрнут на сервере (Docker Compose): app :8000, frontend :3000,
  postgres/redis/centrifugo. Миграции и сидинг правил — автоматически на старте.

**Почему:** нужно было быстро проверить игру вручную и получить общедоступный
стенд для дальнейшей интеграции с Telegram.

**Смысловые решения по деплою:**
- Centrifugo **не публикуется наружу** (клиенты пока работают по REST-поллингу);
  порт откроем и вынесем ключи из dev-конфига при подключении realtime WS.
- На стенде временно `DEBUG=true` — включён dev-логин, чтобы тестер работал по HTTP
  до подключения HTTPS+домена и полноценного Telegram-входа. Для боевого режима
  переключить на `DEBUG=false`.
- Секреты (`JWT_SECRET`, пароль Postgres) генерируются на сервере в `.env`
  (в репозиторий не попадают); `TELEGRAM_BOT_TOKEN` хранится только в серверном `.env`.

**Заметка по безопасности:** Telegram WebApp требует HTTPS+домен — текущий стенд по
HTTP/IP пригоден для теста бэка и тестера, но не для запуска внутри Telegram.
